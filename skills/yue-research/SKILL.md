# 곡 자료 조사·출처 확인 관문

원본의 `researcher`와 분야별 리서처 10종, `document-hunter`, `researchers-verifier`, `verify-sources`를 하나로 합쳤다. 모델과 무관한 기능이지만 **YuE2에서는 가사가 그대로 불리고 사실을 바로잡을 별도 채널이 없으므로** 사실 오류를 생성 전에 막는 것이 중요하다. [공통 규칙](../yue-music/references/common-rules.md)을 적용한다.

"요즘", "인기", "리서치 기반" 같은 유행 조사는 Road Music `docs/music-research.md`의 절차(실행일 기준 출처·기간·지표, 관측 사실과 음악적 해석 구분, AI 추천 플레이리스트와 AI 생성음악 구분)를 따른다.

## 언제 쓰나

- 실존 인물·사건·사건 번호·날짜·금액·인용문이 가사에 들어갈 때
- 다큐멘터리 앨범, 역사곡, 추모곡, 기념곡
- 찬송가·민요 등 원전이 있는 곡(Road Music `docs/hymn-remake-guide.md`도 함께)
- 사용자가 "조사해서", "사실대로" 등을 요청할 때

순수 창작(가상의 이야기, 감정 중심 곡)에는 쓰지 않는다.

## 원칙

1. **1차 자료 우선:** 판결문·공소장·공시·정부 발표·당사자 발언·당시 기록이 2차 보도보다 앞선다. 2차 자료는 1차 자료를 찾는 길잡이로 쓴다.
2. **교차 검증:** 가사에 들어갈 핵심 사실(이름·날짜·숫자·인용)은 서로 독립인 출처 2곳 이상에서 확인한다. 하나뿐이면 "단일 출처"로 표시한다.
3. **링크로 기록:** 모든 출처는 `[이름](URL)` 형태로, 게시일·확인일과 함께 적는다. 읽지 않은 자료를 출처로 쓰지 않는다.
4. **사실과 해석 구분:** 자료가 말하는 것과 곡을 위한 창작적 해석을 나눠 적는다. 가사의 각색은 허용하지만 사실처럼 들리는 거짓 주장은 피한다.
5. **사람의 확인:** 출처 목록은 사용자가 직접 확인해야 다음 단계로 간다. AI의 검증은 사람의 확인을 대신하지 않는다.
6. **개인정보·명예:** 사인(私人)의 개인정보, 확인되지 않은 혐의를 단정하는 표현, 피해자를 특정하는 세부는 넣지 않는다.

## 분야별 1차 자료 위치

| 분야 | 우선 찾을 곳(예) |
| --- | --- |
| 법률 | 법원 판결문·공소장·선고 기록(국내: 대법원 판결서, 해외: PACER/CourtListener 등) |
| 금융 | 공시(국내 DART, 미국 SEC EDGAR), 실적 발표, 감독기관 발표 |
| 정부 | 부처·수사기관 보도자료, 관보, 국회 회의록 |
| 역사 | 국가기록원·도서관 아카이브, 당시 신문(디지털 아카이브), 연구서 |
| 보도 | 탐사 보도 원문, 인터뷰 전문(인용은 원문 대조) |
| 인물 | 당사자 저서·인터뷰·공식 SNS(발언은 원문 링크) |
| 보안 | CVE·보안 권고, 공개 분석 보고서(공격 기법 재현 정보는 가사에 넣지 않음) |
| 기술 | 공식 문서·변경 기록·개발자 발표 |

웹 검색·브라우저는 사용 가능한 도구로 한다. 유료벽·로그인·CAPTCHA를 우회하지 않는다. 문서를 내려받아야 하면 파일명·출처·크기를 알리고 사용자 승인을 받는다.

## 절차

1. **범위 정하기:** 곡이 다룰 사건·인물·기간과 가사에 들어갈 "핵심 사실 목록"을 만든다.
2. **자료 찾기:** 분야별 위치에서 1차 자료를 먼저 찾고, 2차 자료로 빈칸을 메운다.
3. **검증:** 핵심 사실마다 출처 수·출처 간 불일치·단일 출처 여부를 표로 만든다.
4. **기록:** 아래 형식으로 작업 폴더(사용자가 정한 곳, 없으면 곡 프로젝트 옆 `research/`)에 `SOURCES.md`, `RESEARCH.md`를 쓴다. 기존 파일을 덮어쓰지 않는다.
5. **사람 확인 요청:** 출처 목록을 보여주고 사용자가 확인하면 각 항목에 `✅ 확인(날짜)`을 기록한다. 확인 전 상태는 `❌ 확인 대기`.
6. **작사로 넘기기:** 확인된 사실만 `yue-lyric-writer`에 넘긴다. `yue-pre-generation-check`는 확인 대기 항목이 있으면 생성하지 않는다(관문 G8에 포함).

## 기록 형식

```text
# SOURCES.md
| # | 사실(가사에 쓰일 형태) | 출처 | 종류 | 게시일 | 확인일 | 교차 출처 수 | 사람 확인 |
| 1 | (가사에 쓸 사실 문장) | [출처명](URL) | 1차(판결문) | YYYY-MM-DD | YYYY-MM-DD | 2 | ❌ 확인 대기 |

# RESEARCH.md
- 범위 / 시간선 / 인물 관계
- 사실과 창작 해석의 경계
- 단일 출처·불일치 목록
- 가사에 넣지 않기로 한 내용과 이유(개인정보·미확인 혐의 등)
```

## 보고

조사 결과에는 확인한 자료와 해석의 범위, 단일 출처 항목, 사람 확인 대기 항목 수를 적는다. 출처를 다 찾지 못했으면 그렇게 쓴다. 사실 확인이 끝났다는 것과 노래가 사실을 정확히 불렀다는 것은 별개이며, 후자는 생성 후 `yue-result-review`에서 확인한다.
